### [sgl-project/sglang#29604](https://github.com/sgl-project/sglang/issues/29604) — [Feature] Why SGLang doesn't check the input requests' model

- 优先级: high
- 理由: 没有 assignee、没有 linked PR，需求本身合理，但评论里已经点出不能做成默认硬校验：必须兼容 `--served-model-name`、`/v1/models` 暴露的 alias、以及 OpenAI `base-model:adapter-name` LoRA 语法。一个好的切入点是做 opt-in strict mode：只在显式开启时校验 request `model` 是否落在 advertised model names / loaded LoRA 语法集合中，错误返回 OpenAI 风格 `model_not_found`。
- 资源: 主要是 Python API/serving 层改动；不需要大模型或多卡。可以先用 mock `TokenizerManager` / request schema 做单元测试，再用 tiny model 冒烟。
- 验证: self — 单测覆盖 `served_model_name`、raw `model_path`、LoRA `base:adapter`、错误模型名四类；有余力再启动 tiny server 验 `/v1/chat/completions` 错误码。

### [sgl-project/sglang#29709](https://github.com/sgl-project/sglang/issues/29709) — [RFC]: KV Cache Events for HiCache L3 Storage Backends

- 优先级: medium
- 理由: 这是很对口的 ai infra 设计活：SGLang 现在 KV cache events 覆盖 L1 GPU 与 L2 CPU pinned，L3 external storage 还没有事件闭环。没有 assignee、没有 PR。一个适合上手的首 PR 可以不是完整 Mooncake e2e，而是把 RFC 落成文档 + fake L3 backend/event schema + 路由侧单测，先锁定事件语义。
- 资源: 不需要多卡即可做文档、schema、fake backend/unit tests；真实 Mooncake/HiCache e2e 需要额外环境。
- 验证: partial — 本地可以用 fake storage backend 验证 insert/load-back/evict 事件；完整 L3 routing 效果需要维护者或有 Mooncake 环境的人复验。
